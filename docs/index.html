Typed confidence in a non-reasoning decision model, measured across three mathematics benchmarks and 13,110 items. The headline accuracy is unremarkable. What the model does with its own uncertainty is not.

What was measured

A System One model takes a block of text and a typed question, and returns one option plus a probability for every option, in a single forward pass. No chain of thought, no sampling, no text to parse. Jev-1.13 is the first such model.

Multi-step arithmetic is the canonical case where language models benefit from reasoning aloud, so a model that structurally cannot should be poorly suited to it. The interesting question is not only whether it is, but whether it knows it is. Answering that needs difficulty that varies, so the same protocol ran over three benchmarks spanning a 42-point accuracy range, against three chat models on identical items.

MathQA-style
7,473 four-option word problems. Weak instrument: 70.6% of answers are the smallest option.
CompMath-MCQ
1,527 three-option undergraduate items. 23.5% are number-substituted instances of shared skeletons.
HARP
4,110 five-option US competition items, with per-item difficulty levels. The one that actually separates systems.

Findings

Five results, in the order they change what you should believe.

Finding 01

The model withdraws certainty rather than misplacing it

Across the three benchmarks accuracy falls from 96.94% to 54.70%. Over the same range, the fraction of items on which the model commits fully, placing probability 1 on a single option, falls from 53.4% to 5.2%. On the hardest benchmark it commits about once in twenty items.

Accuracy on those committed items barely moves: 100.00%, then 99.79%, then 99.06%. This is the failure mode the result excludes. A component whose confidence stays high while its accuracy falls is worse than useless in a routing system, because it fails silently and at scale.

Finding 02

Deferral works beautifully, until it does not

Abstaining on the least-confident 10% of items lifts accuracy to 99.70% on the easiest benchmark. The same rule on competition mathematics lifts it from 54.70% to only 58.04%.

Thresholding converts confidence into accuracy, and on hard data there is little confidence to convert. This is the honest boundary of the deployment argument: the signal stays informative in both regimes, but what it is worth depends entirely on where your workload sits.

Finding 03

Positional bias is not a model property. It appears under uncertainty

On both easier benchmarks the model's predicted option marginals are indistinguishable from the answer key, which in a single-benchmark study would read as a clean bill of health. On HARP the same test returns p = 2.3 × 10−15. It over-picks the first and last options and avoids the middle.

Splitting by confidence localises it. The divergence lives almost entirely in low-confidence items and vanishes where the model is confident. It is not positionally biased; it falls back on an edge-position heuristic when it does not know. The consequence for practice: a position-bias null measured on a benchmark a model finds easy carries no information about its behaviour on a harder one.

Finding 04

Three of its four confident errors were mistakes in the benchmarks

Across 13,110 items the model answered at full certainty 5,155 times and was scored wrong four times. That is small enough to inspect, so all four were adjudicated by hand against the source mathematics.

Key error
A Gaussian density proportional to exp{−(x−3)²/8} has variance 4. The model answered 4; the key records 2, which is the standard deviation.
Key error
Asked which NumPy function accepts a separate array of weights, the model answered np.average, which has a weights argument. The key records np.mean, which does not.
Key error
For a triangle circumscribing a circle of radius r, the incircle identity K = rP/2 gives P/K = 2/r. The model answered that, as did both other systems that answered. The key records 2/√r.
Model error
Under right-to-left grouping, a ÷ b − c + d reads as a/(b−c−d). The model returned a/(b−c+d), a sign error. This one is real.

The corrected record is 5,154 of 5,155. A second observation follows: if maximum-confidence disagreement with a key is more often a key error than a model error, it is a cheap auditing signal for benchmark quality. Four items to check across 13,110 yielded three corrections.

Finding 05

A no-reasoning protocol cannot be enforced by asking

The chat baselines were told to answer with only a letter and to show no work, at temperature 0 with reasoning effort set to low. One complied. One was billed for hidden reasoning tokens on 93% of items, a mean of 274 per item on the hardest benchmark, and its visible output was still a bare letter. Its accuracy was bought with chain of thought nobody could see.

A third reports zero reasoning tokens but produced 488 replies that exhausted the token budget and returned nothing, which is the signature of deliberation that was never billed. Billed reasoning tokens are a partial diagnostic; unbilled deliberation is not observable at all.

End-to-end accuracy in percent: a reply from which no option can be parsed counts as wrong, because a component that must return a decision has failed to return one. The typed model returned a parseable decision on every one of 13,110 items by construction; the chat baselines failed to on between 7 and 867 items each.

What this does not show

No claim that a System One model is better at mathematics than chat models survives this evidence, and the paper makes none. On competition mathematics it trails a stealth frontier model by 26.6 points.

Contamination cannot be ruled out. All three benchmarks predate or may predate the training cutoffs of the systems measured, and competition mathematics is heavily reproduced online. One benchmark can be shown to be intrinsically easy rather than merely memorised, because a model released seven months before it was published still scores 96.79% on it. The same cannot be established for the typed model, whose training data is undisclosed.

The baseline is narrow: three models, one prompt, one run each, no frontier chat model, and one of the three is an undocumented endpoint whose identity and size cannot be verified. The adjudication of the four confident errors was done by one author; the paper reports as-scored figures throughout so that no headline depends on accepting it.

Reproducing it

Every run recorded the complete unmodified API response, so each number is re-derivable. The analysis is a single deterministic script per phase. Benchmark data is not redistributed; obtain it from the sources below.

MathQA-style
NLP2025-math, Kaggle
CompMath-MCQ
Raimondi et al., arXiv:2603.03334
HARP
Yue et al., github.com/aadityasingh/HARP

One trap worth repeating. When binning the returned probabilities, build histogram edges so the final edge lies strictly above 1.0. Edges accumulated from a floating-point step can stop just below it and silently discard every item whose top probability is exactly 1.0, which on the easiest benchmark is over half the data and precisely the subset carrying the central result.
